# Tabbed shell, habits, cumulative goals

**Status:** implemented on `claude/redesign-foundation` — build, lint, and the
e2e suite pass. Remaining: mobile widths, the add-quote UI in Options, and
Tasks quick-add from any tab.
**Mockups:** `design/redesign-mockups.html` (open in a browser, or read the HTML)

The app moves from day-and-section shaped to session-and-tab shaped. Routines
become standalone habits; goals accumulate toward an outcome instead of
resetting each period.

- **Pinned session zone** below the header, always present. Idle: `ModeSelector`

  and every `CollapsibleSection` are removed. `settings.collapsedSections` stays

## Habits (`store/habits.ts`, key `tt-habits`)

Replaces routines. The `tt-tasks` `routines` / `routineHistory` arrays and
`Task.routineId` are left in storage, unread; `spawnDueRoutines` and the routine
components are deleted. Tasks tagged with a `routineId` stay filtered out of the
task list.

```ts
type HabitFreq =
  | { kind: 'daily' }
  | { kind: 'weekly' }                     // due once in the ISO week
  | { kind: 'everyN'; n: number }          // n >= 2, counted from createdAt
  | { kind: 'weekdays'; days: number[] };  // 0=Mon … 6=Sun

interface Habit {
  id: string;
  name: string;
  freq: HabitFreq;
  target?: { amount: number; unit: string };   // "20 minutes", "10 pages"; absent = plain checkbox
  createdAt: number;
  order: number;
  completions: Record<string, number | true>;  // dateKey → true (checkbox) | logged amount
  archivedAt?: number;
}
```

- **Due today** (`isHabitDueOn` in `goalPeriod.ts`): daily → always; weekly →
  not yet completed this ISO week; everyN → `daysSince(createdAt) % n === 0` or
  overdue; weekdays → `days.includes(weekday(date))`.
- List shows due-today habits; a toggle reveals the rest, dimmed.
- Row readout: **last 7 calendar days** as dots — filled = completed, empty =
  due-and-missed, ring = not due that day.
- Completing a targeted habit logs the amount; reaching `target.amount` marks it.
- Adherence % = completed ÷ due, over a trailing window.

## Goals (`store/goals.ts`, key `tt-goals`, v1 → v2)

```ts
type GoalOutcome =
  | { kind: 'count'; unit: string; target: number }   // 1,000 km · 12 books
  | { kind: 'time'; targetHours: number }
  | { kind: 'open' };

type GoalPeriod = 'daily' | 'weekly' | 'custom';

interface EffortTarget {
  metric: 'time' | 'count';   // time = focus-tracked minutes; count = the outcome unit
  amount: number;
  period: GoalPeriod;
  periodDays?: number;        // custom only
}

interface GoalMilestone { id: string; label: string; doneAt?: number }

interface Goal {
  id: string;
  title: string;
  outcome: GoalOutcome;
  milestones: GoalMilestone[];
  effort?: EffortTarget;
  deadline?: string;          // YYYY-MM-DD; absent = no pace readout
  doneWhen?: string;          // free-text criterion
  evolvesFromId?: string;
  createdAt: number;
  order: number;
  progress: Record<string, number>;   // periodKey → amount logged that period
  archivedAt?: number;
  completedAt?: number;
}
```

- **Invariant:** a goal has an outcome number, **or** ≥1 milestone, **or** an
  effort target. The add form blocks "Create" otherwise.
- `progress` is one map, two readings: *this period vs `effort.amount`*, and
  *sum-of-all-values vs the outcome target*.
- Focusing a goal banks session minutes into the current period's `progress`
  (metric `time`). `+N` logging adds to it (metric `count`).
- **Pace** (only with a `deadline`): compare cumulative progress against the
  straight-line rate `target × elapsed / total`. Without a deadline, the card
  shows "Set a deadline to see whether you're on pace." The `progress` map keyed
  by period already holds everything needed to draw pace for a deadline added
  later.
- **Met** → archive or evolve. Evolve opens the add form with `evolvesFromId`
  pre-set. The lineage renders as a chain on the card and in the dialog.
- Archived goals live behind a disclosure.

### Migration

`tt-goals` v1 → v2, per record: `type: 'time'` → `outcome {kind:'time',
targetHours: target/3_600_000}`; `type: 'counter'` → `outcome {kind:'count',
unit:'times', target}`; `type: 'boolean'` → `outcome {kind:'open'}` + `effort
{metric:'count', amount:1, period}`. The old `period`/`periodDays`/`target` also
seed `effort` for time/counter goals. `progress` is carried as-is. `milestones:
[]`. Nothing is deleted from storage.

v2 → v3 seeds `goal.total` from the sum of `progress` — thereafter `total` is
the authoritative cumulative figure and `progress` is only the per-period
effort ledger.
